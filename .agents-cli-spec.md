# Agent Spec: Kubernetes Log Investigation Agent

## Overview
The Kubernetes Log Investigation Agent is a Python agent built with the Google Agent Development Kit (ADK) on the Gemini Enterprise Agent Platform. It accepts offline Kubernetes container and pod logs (as raw log text or file content), investigates incidents by sanitizing and parsing log streams, identifies failure patterns (CrashLoopBackOff, OOMKilled, probe failures, DNS/network issues, RBAC denials, and configuration errors), correlates evidence along a chronological timeline, and produces a comprehensive analysis report featuring Root Cause Analysis (RCA), exact log line citations, actionable `kubectl` remediation commands, and a structured JSON payload.

## Language
`python`

## Example Use Cases

### Use Case 1: Application OOMKilled (Exit Code 137)
- **Input:** Pod logs showing memory ballooning, Java Heap space exhaustion, and kernel cgroup killer notifications:
  `[2026-09-26T10:14:02Z] java.lang.OutOfMemoryError: Java heap space`
  `[2026-09-26T10:14:05Z] Container memory cgroup limit reached: 512MiB. Process 42 killed with exit code 137.`
- **Expected Output:**
  - Root Cause: Container terminated by cgroup memory limit (OOMKilled, exit code 137) due to Java heap space exhaustion.
  - Supporting Evidence: Lines cited with timestamp and exact snippet.
  - Remediation: Recommended adjustments to `resources.limits.memory` and JVM `-Xmx` flag, plus `kubectl describe pod` command to inspect termination state.
  - Structured JSON summary included.

### Use Case 2: Liveness Probe Failure Cascading Restart
- **Input:** Web service logs showing thread pool starvation followed by HTTP 500/503 errors and liveness probe timeouts:
  `[2026-09-26T11:00:10Z] WARNING: Connection pool exhausted, waiting for active connections...`
  `[2026-09-26T11:00:25Z] ERROR: GET /healthz timed out after 5000ms`
  `[2026-09-26T11:00:30Z] kubelet: Liveness probe failed: HTTP probe failed with statuscode: 500`
- **Expected Output:**
  - Root Cause: Connection pool exhaustion leading to `/healthz` endpoint timeout and subsequent kubelet liveness probe restart.
  - Supporting Evidence: Timeline correlating connection pool warning to probe timeout.
  - Remediation: Database connection pool configuration review, increase `timeoutSeconds` or `failureThreshold` on liveness probe, and verify database health.

### Use Case 3: CoreDNS Resolution / Network Timeout
- **Input:** Microservice connection logs failing to reach dependent service:
  `[2026-09-26T12:05:01Z] dial tcp: lookup payment-service.default.svc.cluster.local on 10.96.0.10:53: no such host`
- **Expected Output:**
  - Root Cause: DNS resolution failure for internal service `payment-service.default.svc.cluster.local`.
  - Supporting Evidence: DNS lookup error cited with timestamp and error message.
  - Remediation: Verify Service name, namespace, and CoreDNS pod health (`kubectl get svc payment-service`, `kubectl get pods -n kube-system -l k8s-app=kube-dns`).

## Tools Required

1. `parse_and_sanitize_logs`:
   - **Purpose:** Ingests raw log text or file content, normalizes timestamps and log levels, masks sensitive information (tokens, passwords, authorization headers), and identifies error/warn anomalous lines.
   - **API / Parameters:** `log_content: str` (raw log text), `file_path: str` (optional path to file).
   - **Auth:** None (offline local processing).

2. `match_k8s_signatures`:
   - **Purpose:** Matches extracted log entries against a Kubernetes failure catalog (OOMKilled, Exit Codes 1, 127, 137, 139, Probe failures, DNS/Connection timeouts, RBAC Forbidden 403, ImagePullBackOff, Missing ConfigMap/Secret, Storage Mount errors).
   - **API / Parameters:** `log_lines: list[str]`.
   - **Auth:** None (offline local pattern matching).

3. `generate_investigation_report`:
   - **Purpose:** Builds the final dual report: a formatted Markdown RCA with chronological evidence timeline, citations, and kubectl remediation, plus structured JSON.
   - **API / Parameters:** `root_cause: str`, `category: str`, `severity: str`, `timeline: list[dict]`, `evidence_citations: list[dict]`, `remediation_steps: list[str]`, `kubectl_commands: list[str]`.
   - **Auth:** None.

## Constraints & Safety Rules
- **Data Privacy & Sanitization:** All bearer tokens, passwords, secrets, private keys, and authorization headers found in logs must be masked/redacted in both analysis and citations.
- **Evidence Grounding:** Every claim, line citation, and timestamp in the investigation report must directly correspond to content in the input logs. Hallucinating log snippets is strictly prohibited.
- **Non-Destructive:** Analysis is strictly offline and read-only.
- **Clear Separation:** Output must provide both human-readable Markdown and machine-readable JSON without sacrificing clarity.

## Success Criteria
- **Task Success:** >= 90% score on `multi_turn_task_success` or `final_response_quality` in `agents-cli eval run`.
- **Evidence Accuracy:** 100% of cited evidence lines in test cases accurately match the source log entries.
- **Diagnosis Precision:** Correctly identifies root causes and k8s failure categories across all benchmark incident scenarios (OOM, CrashLoop, Probes, DNS, RBAC).
