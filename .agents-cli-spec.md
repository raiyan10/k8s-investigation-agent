# Agent Spec: Kubernetes Log Investigation Agent

## Overview
The Kubernetes Log Investigation Agent (`k8s_investigator`) is a Python SRE agent built with the Google Agent Development Kit (ADK) on the Gemini Enterprise Agent Platform (`agent_runtime`). It investigates Kubernetes incidents by querying a live GKE cluster through an in-cluster Model Context Protocol (MCP) Server (`McpToolset` over Streamable HTTP) or local `kubectl` tools, as well as by ingesting offline pod/container logs. It automatically saves structured findings from every investigation into the **Agent Platform Memory Bank** (`HybridMemoryBankService`) and recalls past incidents with zero redundant tool calls when troubleshooting recurring or related cluster issues.

## Language
`python`

## Example Use Cases

### Use Case 1: Application OOMKilled (Exit Code 137)
- **Input:** Pod logs showing memory ballooning, Java Heap space exhaustion, and kernel cgroup killer notifications:
  `[2026-09-26T10:14:02Z] java.lang.OutOfMemoryError: Java heap space`
  `[2026-09-26T10:14:05Z] Container memory cgroup limit reached: 512MiB. Process 42 killed with exit code 137.`
- **Expected Output:**
  - Root Cause: Container terminated by cgroup memory limit (OOMKilled, exit code 137) due to Java heap space exhaustion.
  - Supporting Evidence: Lines cited with timestamp and exact snippet.
  - Remediation: Recommended adjustments to `resources.limits.memory` and JVM `-Xmx` flag, plus `kubectl describe pod` command to inspect termination state.

### Use Case 2: Liveness Probe Failure Cascading Restart
- **Input:** Web service logs showing thread pool starvation followed by HTTP 500/503 errors and liveness probe timeouts:
  `[2026-09-26T11:00:10Z] WARNING: Connection pool exhausted, waiting for active connections...`
  `[2026-09-26T11:00:25Z] ERROR: GET /healthz timed out after 5000ms`
  `[2026-09-26T11:00:30Z] kubelet: Liveness probe failed: HTTP probe failed with statuscode: 500`
- **Expected Output:**
  - Root Cause: Connection pool exhaustion leading to `/healthz` endpoint timeout and subsequent kubelet liveness probe restart.
  - Supporting Evidence: Timeline correlating connection pool warning to probe timeout.
  - Remediation: Database connection pool configuration review, increase `timeoutSeconds` or `failureThreshold` on liveness probe, and verify database health.

### Use Case 3: Cross-Session Memory Bank Recall (`ImagePullBackOff` / Recurring Workload Regression)
- **Input (Session 1):** Investigate `imagepull-test-pod` or `payment-api-v1` crash.
- **Input (Session 2):** Ask about the same pod (`imagepull-test-pod`) or a sibling pod (`imagepull-test-pod-2`) or upgraded workload (`payment-api-v2`).
- **Expected Output:**
  - When the exact pod was already diagnosed in `<PAST_CONVERSATIONS>`, responds directly from Memory Bank with 0 tool calls.
  - When a related workload revision (`payment-api-v2`) fails with a recurring root cause, correlates current findings with the recalled Memory Bank incident.

## Tools & Services

1. `get_pods_info`, `get_nodes_info`, `get_pod_logs`, `get_pod_events`, `get_deployment_history`, `investigate_kubernetes_logs`:
   - **Purpose:** Live read-only Kubernetes cluster inspection exposed via the in-cluster FastMCP Server (`app/mcp_server.py`) over Streamable HTTP (`/mcp`) with Bearer token authentication, and locally as `FunctionTool` fallbacks (`app/tools.py`).
2. `restart_deployment` & `get_secret` (Governed by Agent Gateway Least-Privilege Policy):
   - **Purpose:** Registered on the MCP server (`app/mcp_server.py`) to demonstrate end-to-end **Agent Gateway (`AGENT_TO_ANYWHERE`) & Least-Privilege Policy (`k8s-investigator-least-privilege-policy`)** enforcement. When the least-privilege policy is active, mutating operations (`restart_deployment`) and secret exfiltration (`get_secret`) are strictly blocked for the agent's SPIFFE identity while read-only diagnostic tools remain permitted.
3. `parse_and_sanitize_logs` & `match_k8s_signatures`:
   - **Purpose:** Ingests raw log text or file content, normalizes timestamps and log levels, masks sensitive information (tokens, passwords, authorization headers), extracts error/warn anomalous lines, and classifies logs against 13 Kubernetes failure signatures.
4. `generate_investigation_report`:
   - **Purpose:** Builds the structured plain-text RCA report with chronological evidence timeline, citations, and `kubectl` remediation commands.
5. `PreloadMemoryTool` & `HybridMemoryBankService`:
   - **Purpose:** Automatically recalls past Kubernetes incident investigations at the start of each turn (`<PAST_CONVERSATIONS>`) with boundary-safe Kubernetes identifier scoring and persists new incident summaries after each turn (`save_investigation_to_memory`).

## Constraints & Safety Rules
- **Verifiable Agent Identity (SPIFFE ID) & Audit Attribution:** Deployed with Google Cloud Agent Identity (`AGENT_IDENTITY`), passing the agent's SPIFFE ID (`X-Agent-Spiffe-Id`) to the in-cluster MCP server, which verifies it and uses Kubernetes User Impersonation (`--as=<spiffe-id>`) so all GKE Audit Logs attribute read-only `get/list/watch` queries to the specific AI agent's SPIFFE identity rather than a shared service account.
- **Agent Gateway & Least-Privilege Governance (`AGENT_TO_ANYWHERE`):** Outbound MCP and tool calls are governed by `k8s-investigator-gateway` (`projects/golden-keel-509807-r8/locations/us-east1/agentGateways/k8s-investigator-gateway`) and the `k8s-investigator-least-privilege-policy` (`deployment/gateway/least-privilege-policy.yaml`), which matches the client certificate URI SAN against the agent's SPIFFE ID, allows only read-only diagnostic tools, and explicitly blocks `restart_deployment` and `get_secret`.
- **Data Privacy & Sanitization:** All bearer tokens, passwords, secrets, private keys, and authorization headers found in logs must be masked/redacted in both analysis and citations.
- **Evidence Grounding:** Every claim, line citation, and timestamp in the investigation report must directly correspond to content in the input logs or cluster events.
- **Non-Destructive:** Cluster inspection is strictly read-only (`get`, `list`, `watch`).
